Build a complete, production-ready A/B test system for a truthful, time-bound Graylock Digital “Build-Fee Waiver” promotion.

Do not redesign or alter the existing homepage sections, hero, offer, reviews, portfolio, pricing, booking flow, form fields, navigation, footer, or current CTA destinations. Add only:

1. A promotion-popup experiment system
2. Two popup copy variants
3. A no-popup control group
4. Persistent experiment attribution through the existing Homepage Direction form and downstream lead workflow
5. A secure internal experiment dashboard
6. Campaign configuration, kill switch, and preview tools

IMPORTANT COMMERCIAL RULES:

- This is a real promotion, not fake scarcity.
- Never use “offer ends when you close this window.”
- Never show a fake countdown timer.
- Never use “selected,” “winner,” “award,” “free website,” or “enter to win.”
- The promotion must clearly state that Graylock is waiving the STANDARD BUILD FEE only.
- The applicable monthly plan remains paid.
- The promotion applies only if Graylock confirms the business is a fit and the prospect chooses to move forward after reviewing a Homepage Direction.
- The promotion deadline must be a real configurable date/time. When the campaign ends, the popup must stop showing automatically.
- Do not imply Google rankings, lead volume, booked appointments, revenue, compliance, or any other outcome guarantee.
- Do not add 50%-off monthly pricing, second-place offers, or any additional discount.
- Do not change the existing build-fee amount, plan pricing, guarantee language, or Terms of Service.

────────────────────────────────────────
PART 1 — EXPERIMENT STRATEGY AND VARIANTS
────────────────────────────────────────

Build three experiment arms:

1. CONTROL
   - No promotion popup is shown.
   - The existing homepage remains unchanged.
   - Existing Homepage Direction CTAs and form flow continue to work.
   - Track the assigned Control variant through the existing form and lead workflow if that visitor later submits.

2. VARIANT A — SAVINGS-LED POPUP
   - Show a truthful build-fee-waiver popup.
   - Lead with the direct financial value of the promotion.

3. VARIANT B — HOMEPAGE-DIRECTION-LED POPUP
   - Show a truthful build-fee-waiver popup.
   - Lead with the existing low-risk Homepage Direction value event, then explain the build-fee waiver.

IMPORTANT TEST DEPLOYMENT RULE:

Build all three arms now, but configure the initial live experiment as:

- Control: 50%
- Variant A: 50%
- Variant B: 0%

This is Stage 1. The first objective is to determine whether a popup improves qualified demand compared with no popup.

The dashboard must allow an authorized admin to later activate Stage 2 with configurable traffic allocation, such as:

- Control: 10%
- Variant A: 45%
- Variant B: 45%

Do not activate Variant B in production by default.

PART 3 — STICKY EXPERIMENT ASSIGNMENT
────────────────────────────────────────

Implement persistent, sticky visitor assignment.

Requirements:

- Persist a stable assignment for the entire campaign duration.

────────────────────────────────────────
PART 4 — POPUP TRIGGER, SUPPRESSION, AND UX
────────────────────────────────────────

Only Variant A and Variant B may show a popup.

The popup should appear only after BOTH conditions are met:

1. The homepage intro, if present, has fully finished and the homepage is interactive.
2. The visitor has spent at least 25 seconds on the page.
3. The visitor has reached at least 55% scroll depth.

Do not show the popup immediately on landing.

Do not use aggressive exit intent in this first release.

If the visitor closes the popup or clicks “No thanks”:

- Track the dismissal.
- Do not show it again to that browser during the active campaign unless an authorized admin changes the campaign frequency setting.
- Do not create a delayed second popup in the same session.
- Do not open chat or another modal afterward.

If the visitor clicks the popup CTA:

- Track the click.
- Open the existing Homepage Direction / fit-call form or use the existing approved CTA behavior.
- Do not create a duplicate form or a separate booking system.
- Pass promotion source and experiment attribution into the existing form as hidden metadata.
- Suppress the promotion popup for that visitor immediately after the CTA click.

────────────────────────────────────────
PART 5 — POPUP VISUAL DESIGN
────────────────────────────────────────

IMPORTANT DESIGN DECISION:

Do NOT use an image, stock photo, AI image, illustration, device mockup, decorative icon, countdown timer, badge, or visual “prize” treatment in either popup.

The popup must be text-led and identical in visual design across Variant A and Variant B. The only difference between the two variants must be the approved copy framing. This prevents visual differences from contaminating the copy test.

The visual direction should feel like a restrained, premium Graylock agency announcement—not like a SaaS modal, coupon popup, casino promotion, giveaway, or discount-site overlay.

DESKTOP MODAL:

- Centered dialog over a subtle, non-distracting dark backdrop overlay.
- Maximum width: approximately 520px.
- Use the existing Graylock dark charcoal / near-black visual language.
- Use a warm off-white panel or charcoal panel according to the existing site’s strongest modal styling. Prefer a deep charcoal panel if it maintains strong contrast.
- Use a thin restrained orange border accent or a short orange rule near the top. Do not use a thick border.
- Use existing display typography for the headline.
- Use existing body typography for body copy and terms.
- Use the current brand orange for the primary CTA.
- Use a visible close “X” control in the upper-right corner.
- Use one primary CTA and one low-emphasis text dismissal action.
- Use generous vertical spacing.
- Keep the design calm, readable, and premium.
- Do not use rounded “coupon” styling, starbursts, badges, percentage graphics, celebratory confetti, animated dollar signs, or urgency clocks.

MOBILE MODAL:

- Use a bottom-sheet modal with a subtle top radius consistent with existing Graylock styles.
- Full width minus comfortable side margins.
- Keep the close button visible and easy to tap.
- Keep the primary CTA full-width.
- Keep the deadline/terms line visible without requiring scroll where reasonably possible.
- Avoid excessive vertical height. The core offer, terms line, CTA, and dismissal must be readable in one normal mobile view.
- Do not lock the visitor into the popup or make dismissal difficult.

MOTION:

- Use only a subtle 160–220ms fade and slight vertical transition.
- Respect prefers-reduced-motion.
- Do not use attention-grabbing shake, bounce, pulse, timer, or looping animation.
- Do not block page scrolling before the popup appears.
- When the modal is open, use accessible dialog focus management and restore focus to the triggering context after close.

ACCESSIBILITY:

- Implement a semantic accessible dialog/modal.
- Add aria-modal="true".
- Add a meaningful aria-labelledby heading relationship.
- Trap keyboard focus while open.
- Allow Escape to close.
- Ensure the close button has aria-label="Close promotion".
- Ensure the “No thanks” action is keyboard accessible.
- Maintain strong color contrast.
- Do not rely on color alone to communicate terms or status.
